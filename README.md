# 웹게임교실

바이브코딩으로 첫 웹게임을 만드는 중학교 1학년 대상 45장 수업입니다. 45분 × 3차시, 휴식 10분 × 2회, 총 155분입니다.

## 사용 주소

- 수업: https://jeonggunhwa.github.io/webgame-classroom/
- Sites: https://webgame-classroom.wjdrmsghk.chatgpt.site/
- 강사: https://jeonggunhwa.github.io/webgame-classroom/#admin
- 소스: https://github.com/jeonggunhwa/webgame-classroom
- Firebase 콘솔: https://console.firebase.google.com/project/web-game-classroom/overview

## 온라인 연결

Firebase Realtime Database(싱가포르), Google 강사 로그인, 학생 익명 인증을 사용합니다. 승인된 강사 계정만 수업 콘텐츠·진행·공개 정책·타이머를 변경할 수 있습니다. Google에 로그인했다는 이유만으로 강사 권한이 생기지 않습니다.

학생은 강사가 안내한 숫자 4자리 참여코드, 학번(숫자 2~12자리), 이름(1~40자)을 입력해 입장합니다. 개인 비밀번호나 학생 Google 계정은 필요하지 않습니다. 내부적으로 Firebase 익명 인증을 사용하며, 학번·이름은 출석용 자기신고 정보로 별도 본인확인 절차가 아닙니다. 학번·이름·입장 시각은 해당 학생과 강사만 열람할 수 있고, 다른 학생에게는 공개하지 않습니다. 질문은 참여자에게 익명으로 공유되고, 퀴즈 답안은 본인과 강사만 열람합니다. 후기는 기본 비공개이며 강사가 승인한 본문만 공개합니다. 승인된 후기 수정 시 다시 비공개로 전환됩니다. 익명 인증도 서버 식별자가 생기는 방식으로 완전한 익명성을 뜻하지 않습니다. 학번·이름은 입장 폼에만 입력하고 질문·후기 본문에는 연락처·사진 등 개인정보를 올리지 마세요.

강사 로그인 후 웹슬라이드의 이전·다음·방향키·목차 이동은 기본적으로 학생 화면에 실시간 반영되고 강사 진행 잠금이 켜집니다. 강사는 잠금 상태에서도 이동할 수 있습니다. 교사용 비공개 미리보기를 켜면 학생 잠금이 해제되며, 실시간 진행을 다시 켜면 현재 강사 위치로 모입니다. PDF·자료 공개는 학습 UI 운영 정책이며 이미 받은 공개 콘텐츠의 복사 방지/DRM이 아닙니다.

무료 Spark 요금제를 사용하며 결제·유료 업그레이드는 설정하지 않았습니다. 요금제 한도에 도달하면 제한될 수 있습니다. 인증 및 데이터 동기화에는 인터넷이 필요합니다. 온라인 연결 또는 인증 실패 시 입장과 기록 저장을 진행하지 않습니다. 인터넷 없는 수업은 별도 오프라인 파일을 사용하세요.

## 파일

- index.html: 온라인 시작 화면
- 웹게임교실.html: 온라인 단일 HTML(인증·SDK에는 인터넷 필요)
- 오프라인-웹게임교실.html: 기존 오프라인 버전, 실제 로그인/다른 기기 동기화 없음
- 별잡기.html: 독립 게임
- assets/content.js: 수업 본문과 슬라이드
- assets/cloud.js: 인증·서버 저장·구독 경계
- assets/config.js: 공개 Firebase 웹 구성값. 비밀번호·서비스 계정 키 아님
- assets/landing.js / landing-qr.svg: 첫 슬라이드 공개 주소·QR. 참여코드는 포함하지 않음
- database.rules.json: Firebase에 게시한 서버 보안 규칙의 소스

Firebase SDK 11.10.0 compat CDN에서 app → auth → database를 로드한 뒤 config → content → game-source → landing → cloud → app 순으로 실행합니다. 빌드 단계가 필요 없는 정적 사이트이며 main 브랜치 변경은 GitHub Pages로 자동 배포됩니다.

## 운영 주의

브라우저 캐시나 localStorage 값으로 강사 권한을 부여하지 않습니다. 서버 보안 규칙이 권한을 검사합니다. 학생 명단·후기·질문이 들어 있는 운영 백업은 공개 저장소에 올리지 마세요. 수업 후 운영 기록을 백업·정리하고 개인정보 보관 기간을 정하세요. 강사는 공용 PC에서 반드시 강사 로그아웃을 하세요.

콘솔에서 보안 규칙을 바꾸면 database.rules.json도 같이 갱신해야 합니다. 소스 수정 후 단일 HTML 및 ZIP은 다시 생성해야 합니다. AI API·문자·메일·결제는 연결하지 않았습니다.

강의 화면과 설명을 참고해 독립 재구성한 자료이며 강사 원본 복제본은 아닙니다.

## 학생 입장과 명단

수업 주소 또는 첫 슬라이드 QR로 접속해 학번·이름과 숫자 4자리 참여코드를 입력합니다. 학교 이메일은 사용하지 않습니다. 참여코드는 관리자 대시보드에서 확인·변경하며, 변경 즉시 이전 코드와 이전 입장권은 무효가 되어 학생이 새 코드로 다시 입장해야 합니다. 관리자에서 추가 수강 승인 기능을 켠 경우에는 정보 입력 후 강사 승인이 추가로 필요합니다. 명단의 학번·이름은 공개 후기·질문 본문과 분리해 저장합니다. 학생은 자신의 입력만 읽고 수정할 수 있고 강사만 전체 명단을 볼 수 있습니다.

공용 기기를 넘길 때는 학생 나가기를 사용합니다. 출석 정보는 강사 기록에 남으며, 개인정보 보관·삭제 기간은 수업 운영자가 정해야 합니다. 서로 다른 기기에서 같은 학번·이름을 입력해도 본인 확인이나 계정 복구로 취급하지 않습니다. 입력한 정보가 실제 학생과 일치하는지는 강사가 확인해야 합니다.

## 참여코드와 개인정보 경계

참여코드는 강사 전용 entrySettings에 저장하고, 서버 규칙이 학생의 입장권 발급을 검사합니다. 코드 원문은 공개 진행 상태, 질문·후기, 콘텐츠/운영 내보내기, 브라우저 임시 작성값, QR, URL에 넣지 않습니다. QR은 공개 랜딩 주소만 포함합니다. 숫자 4자리 코드는 수업 참여 확인용이며 강력한 본인 인증이나 시험용 보안 수단이 아닙니다. 학번·이름도 출석용 자기신고입니다.

새 기기·공용 PC에서는 다시 입장해야 합니다. 학생 나가기를 누르면 해당 기기의 익명 세션이 바뀌므로 기존 명단을 복구하지 않습니다. 사이트 파일/백업에 실제 참여코드를 적거나 공개 저장소에 올리지 마세요.
